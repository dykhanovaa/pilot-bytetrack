# Технический пилот ByteTrack SkipAware v1

Исполняемый пилот для ultralytics 8.3.0. Основная серия и проверки H1/H2 не выполнялись.

## Данные для преподавателя

В `data/images/` сохранены исходные кадры технического пилота и дополнительные примеры классов, в `data/annotations/` — XML-разметка. Это часть UA-DETRAC: кадры 1–120 трёх test-видео и отдельные кадры аудита, а не полный датасет основной серии. Описание состава и происхождения — в `data/README.txt`. В Git разрешены все файлы проекта, включая данные, веса, архивы, результаты и отчёты. Исключаются только виртуальные окружения и кэши.

## Воспроизведение

Python 3.12.14, macOS arm64, CPU. Установить зависимости из `requirements.lock` в отдельное окружение. В архиве TrackEval используется commit `12c8791b303e0a0b50f753af204249e622d0281a`. Если vendor отсутствует, клонировать официальный `https://github.com/JonathonLuiten/TrackEval` и перейти на этот commit. Выполнить:

```sh
.venv/bin/python patch_trackeval.py
.venv/bin/python fetch_data.py
.venv/bin/python synthetic.py
.venv/bin/python pilot.py
.venv/bin/python class_check.py
```

Веса `yolov8n.pt`: https://github.com/ultralytics/assets/releases/download/v8.3.0/yolov8n.pt
SHA-256: `f59b3d833e2ff32e194b5bb8e08d211dc7c5bdf144b90d2c8412c47ccfc83b36`.

Файлы данных закреплены на Hugging Face `sunnycloudhust/TrafficVision`, revision `47b78997538030f06a3013d2a119bdfda025982f`. Скрипт подготовки использует именно эту revision. Манифест содержит URL и SHA каждого файла. Исходный архив train-аннотаций дополнительно получен по ссылке `https://drive.google.com/uc?export=download&id=12xJc8S0Z7lYaAadsi2CoSK3WqH2OkUBu`; все 60 XML побайтно совпали с зеркалом. При повторном запуске сравнить SHA с `data/sources.json` и `evidence/file_hashes.json`.

## Исходники TrackEval в репозитории

`vendor/TrackEval` хранится как обычная папка с исходниками, а не вложенный Git-репозиторий или подмодуль. Поэтому при клонировании проекта преподаватель получит и код оценщика. Исходный commit, источник и контрольные суммы совместимого патча записаны в `vendor/TrackEval/UPSTREAM.json`. Паспорт пилота читает эту версию из манифеста; отдельная папка `.git` внутри TrackEval для запуска не требуется. Лицензия исходного проекта сохранена.

## Что изменено в трекере

`SkipAware.step(observed=True)` передаёт настоящий результат детектора в штатный `BYTETracker.update`, даже если результат пуст. `observed=False` не вызывает update: увеличивает исходный номер кадра, выполняет однокадровый штатный прогноз для подтверждённых и потерянных треков, сохраняет неподтверждённые до следующего наблюдения и применяет срок удаления в 25 исходных кадров. На пропуске выдаются только прогнозы подтверждённых tracked-треков; lost и unconfirmed не выдаются. Неподтверждённые не прогнозируются: их сопоставление на следующем наблюдении соответствует штатной ветке unconfirmed. Это ограничение адаптации при большом перемещении, а не обещание устойчивости при любом k. Входа из будущего нет. k=1 полностью совпадает со штатной реализацией на искусственных и реальных данных.

Это **адаптация управления наблюдениями и выдачей**, а не неизменённый ByteTrack. Используется одно правило при всех k. В синтетическом сравнении глобальный счётчик ID сбрасывается между независимыми запусками; одновременно запущенные в одном процессе трекеры не используются.

## Содержимое

- `protocol.json`: замороженные k=1..10, H1/H2 и единое определение k_max только по HOTA.
- `skip_aware.py`: адаптация и корректный конструктор Boxes, включая вход (0,6).
- `synthetic.py`: два сценария по 150 кадров × 10 k × два метода, проверки позднего входа, короткого и длинного исчезновения, пустого наблюдения, совпадения k=1.
- `pilot.py`: конвертер, проверка координат и ignored regions, детектор, 90 сравнений трёх режимов на 3 технических фрагментах, TrackEval, оценка на общих S_k, манифест и паспорт.
- `class_check.py`: дополнительные изолированные test-кадры для проверки четырёх типов GT. Они не входят в исследовательскую выборку.
- `trackeval_numpy.patch`: только замена удалённых алиасов np.float/np.int в используемых модулях. Формулы метрик не изменены. Требуются commit **и** этот patch.
- `evidence/checks.log`: успешные проверки; `synthetic_*` и `trace_*`: входы, состояния, ID по каждому кадру.
- `evidence/metrics_full_frames.csv`: технические метрики HOTA, DetA, AssA, IDF1, IDSW. `metrics_sampled_frames.json`: парные сравнения на S_k.
- `evidence/frames`: GT зелёным, выход адаптации красным, ignored regions серым; в заголовке указан измерительный либо прогнозный кадр.
- `evidence/class_frames`: дополнительные кадры аудита таксономии.
- `evidence/main_manifest.json`: 60 train-последовательностей, группы и плотности; **основные изображения ещё не скачаны**.

## Ограничения

Пилот — техническая проверка, не исследовательский результат и не оценка скорости. Детекции всех 360 кадров получены заранее для одинакового входа сравниваемых трекеров. Три прогревочных вызова служат только техническому запуску; основной протокол времени предусматривает 100 вызовов и пять полных повторов. Кэш не допускается при основном замере времени. H1/H2, доверительные интервалы и k_max в пилоте не рассчитываются.

В XML есть отсутствующие номера кадров. Они не считаются пустым GT. Для основной серии на них нужно обрабатывать видео в исходном времени, но маскировать GT и выходы при оценке, а плотность считать по размеченным кадрам. В трёх пилотных отрезках 1–120 разметка непрерывна. Реальных пустых GT-кадров в этих отрезках нет; пустые кадры проверены искусственно и входом чёрного изображения в настоящий детектор.

COCO motorcycle исключён. COCO car/bus/truck объединяются с четырьмя группами UA-DETRAC в vehicle; ван и специальные автомобили не получают выдуманного отдельного COCO-класса. Аудит проверяет конкретные боксы, а не доказывает полную эквивалентность двух таксономий.
