# Технический пилот ByteTrack SkipAware

Проверка отслеживания транспортных средств при запуске детектора через `k = 1…10` кадров. Используются YOLOv8n, ByteTrack из `ultralytics 8.3.0` и TrackEval.

SkipAware различает пропуск запуска детектора и настоящий пустой результат. На пропущенных кадрах сохраняются неподтверждённые треки и выдаются прогнозы подтверждённых. Будущие кадры не используются. При `k = 1` результаты совпадают со штатным ByteTrack; при больших интервалах ошибки сопоставления остаются возможными.

## Установка и запуск

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
```

Запускать из корня проекта:

```sh
# Искусственные последовательности с идеальными детекциями
.venv/bin/python run_pilot.py --mode synthetic

# Реальные кадры, YOLOv8n и оценка TrackEval
.venv/bin/python run_pilot.py --mode real

# Оба этапа
.venv/bin/python run_pilot.py --mode all
```

Если данные отсутствуют, предварительно выполнить `.venv/bin/python fetch_data.py`. Веса — `yolov8n.pt`. Дополнительная проверка типов транспорта запускается командой `.venv/bin/python class_check.py`.

## Данные и результаты

В `data/images/` находятся кадры 1–120 трёх test-видео UA-DETRAC: `MVI_39031`, `MVI_39051`, `MVI_39211`, а также отдельные кадры аудита. XML-разметка хранится в `data/annotations/`. Это часть датасета; состав и происхождение описаны в [data/README.txt](data/README.txt).

Каждый запуск создаёт отдельную папку `runs/<дата-время>/`:

- `summary.csv`, `states.csv` — результаты искусственных сценариев и состояния треков;
- `metrics_full_frames.csv` — HOTA, DetA, AssA, IDF1 и IDSW;
- `metrics_sampled_frames.json` — сравнение на общих выбранных кадрах;
- `trace_*.json` — входные детекции, состояния и выданные ID;
- `frames/` — GT зелёным, результаты красным, ignored regions серым;
- `passport.json` и журналы — параметры среды и проверки.

Первоначальные результаты сохранены в `evidence/`, отчёты — в `documents/`.

## Основные файлы

- `skip_aware.py` — адаптация ByteTrack;
- `synthetic.py` — поздний вход, исчезновение и возвращение объектов;
- `pilot.py` — сквозной прогон и оценка;
- `protocol.json` — параметры исследования;
- `vendor/TrackEval/` — код оценщика, версия и контрольные суммы в `UPSTREAM.json`.

Совместимый NumPy-патч применяется при запуске автоматически. Подробные инструкции — в [QUICKSTART.txt](QUICKSTART.txt).

Пилот проверяет работоспособность системы. Основная серия на 60 видео, проверки H1/H2 и расчёт `k_max` не выполнялись. Детекции кэшируются для одинакового входа трекеров, поэтому результаты пилота не являются измерением ускорения.
